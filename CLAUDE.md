## Project Overview

ERGMRank.jl is a Julia port of the R `ergm.rank` package (from the StatNet collection) for fitting Exponential Random Graph Models to rank-order networks, where each actor assigns ordinal ranks to a subset of other actors.

## Architecture

The entire package lives in a single source file: `src/ERGMRank.jl`. It is organized into these sections:

1. **RankNetwork** -- dense `Matrix{Int}` of rank values; row i = ego i's ranking of the alters, GREATER value = HIGHER standing (ergm.rank convention). The complete-ranking invariant (each row's off-diagonal is a permutation of `1:(n-1)`) is validated at construction (`RankNetwork: not a valid complete ranking — ego i's ranks … are not a permutation of 1:(n-1)`), preserved by `swap_ranks!` (the AlterSwap move), and checkable with `is_valid_ranking`. `as_rank_network(mat)` refuses a matrix with `missing`/`nothing` (a rank has no face value, so there is no `missing=` policy to offer — the message points at the Networks.jl missing-data guide) and non-integer values, with `ArgumentError`s that say so.

   **`as_rank_network(net::Network; attr=:rank, missing=:error, report=false)` is the `Network`→`RankNetwork` adapter of the ecosystem conversion contract** (panel items 4/13; R's `as.matrix(nw, attrname="rank")` on `newcomb`). It preserves the actor set and the ranks (edge attribute `attr` on every arc `i → j`); REJECTS with an `ArgumentError` that says why an undirected network (rankings are ego-specific), a two-mode network, a masked dyad (`require_observed(net, :error; context="as_rank_network", face_ok=false)` — `supports_missing(as_rank_network) == true`, `missing_policies(as_rank_network) == (:error,)`; `missing=:face` is refused with the reason: an unobserved rank has no face value to condition on, so `:face` is deliberately NOT offered and the guard's error must not suggest it), an arc without a rank, a non-integer rank and an ego whose ranks are not a permutation (the message names the ego AND the attribute, reusing `_ranking_violation`); and with `report=true` returns `(rnet, ConversionReport(:Network, :RankNetwork))` with one `record_drop!` per other edge attribute, vertex attribute, network attribute and self-loop arc. The adapter testset is the citation of the `Network`→`RankNetwork` column in `Networks.jl/docs/src/guide/conversion_invariants.md`. Do not add a `:face` policy here; do not read a masked arc.

   **Display** follows Networks.jl's convention: two-arg `show` is the ONE-LINE form (`RankNetwork(4 actors)`, `RankERGMModel(1 term, 4 actors, CompleteOrder)`, `RankERGMResult(swap-MPLE, 2 terms, converged)` — what `print`/`string` and containers use, so a `Vector{RankNetwork}` of draws prints one line per element), and the block (rank matrix up to 12 actors; the R-style results table) is the `MIME"text/plain"` method the REPL calls. Tests that assert on the block use `sprint(show, MIME("text/plain"), x)`; never put the block back in the two-arg method.
2. **Reference measure** -- `CompleteOrderReference`: discrete-uniform over complete orderings (constant; cancels from likelihood ratios; the constraint is what matters).
3. **Terms** -- `RankDeference`, `RankNonconformity(:all/:localAND)`, `RankNodeICov`, `RankInconsistency`, `RankEdgeCov`, implemented from ergm.rank's `wtchangestats_rank.c` summary functions and golden-master tested against R ergm.rank 4.1.2 through the PROVENANCED fixture `test/fixtures/rank_terms.toml` (generated by `test/fixtures/r/rank_terms.R`, a `summary()` call: all six statistics on the 4-actor README network and on a seeded 8-actor ranking with frozen covariates/reference, `check_golden` at 1e-9 — never bare literals). `RankNodeICov(:age)`/`RankEdgeCov(:x)` (ERGM.jl's attribute-name spelling) are refused by dedicated constructors that say to pass the values (`vertex_attribute_vector(net, :age, Float64)`), since a `RankNetwork` carries no attributes. **Known limitation, stated everywhere (README, terms guide, docstring, CHANGELOG):** ergm.rank's `rank.nonconformity` `local1`/`local2`/`geometric`/`thresholds` variants are NOT implemented; the constructor refuses them with `RankNonconformity: variant must be :all or :localAND (got :local1); ergm.rank's local1/local2/geometric/thresholds variants are not implemented in ERGMRank.jl` (the exact text is pinned) — never fall back to `:all` silently. A wrongly sized covariate is refused by BOTH `compute` and `swap_change` with a message naming the term (`_bad_nodeicov_length`, `_bad_matrix_size`), so the fitter, the sampler and `gof` all say the same thing. **The term contract: every term implements `compute(term, rnet)` AND `swap_change(term, rnet, ego, j, k)`** (exported) — the change `g(y_swapped) − g(y)` when ego swaps its ranks of j and k, ported from the `wtchangestats_rank.c` change functions. A swap changes ego's comparison of exactly the alter pairs containing j or k, so `_sum_changed_pairs(f, y, n, ego, j, k)` visits those ordered pairs once with `d = ±1` and each term supplies the multiplier (deference: the two off-row factors; nodeicov/edgecov: the covariate difference; inconsistency: agreement with the reference flips); the nonconformity variants additionally loop over the matched actor (`:all`) or enumerate the triples containing j or k (`:localAND`) — O(n) and O(n²) respectively, 0 bytes, never a recomputation of a full statistic. **There is no brute-force fallback method**: `_swap_delta_bruteforce` (two `compute`s, swap and restore) is the TEST ORACLE only, and every `swap_change` is asserted `==` to it (exact — integer counts, integer-valued covariates in the tests) on 200 random cases at n ∈ {4, 5, 8} and on every swap of the 4-actor R network. `_swap_delta!(delta, terms::Tuple, rnet, ego, j, k)` fills the kernel's workspace with one `swap_change` per term, `@generated` over the tuple type (ERGM's `_change_stat_tuple` pattern — no `map` cliff at 32 terms), 0 bytes pinned at p = 2 and p = 8; `_swap_delta` is the allocating convenience form. Adding a term means adding both methods and a row in the oracle testset.
4. **Estimation** -- `fit_ergm_rank` (aliases `ergm_rank` — the R-faithful name — and `fit_rank_ergm`, a DEPRECATED BINDING: `const` + `Base.deprecate(@__MODULE__, :fit_rank_ergm)` spelled out as `@deprecate_binding` expands, docstring attached to the `const` BEFORE the deprecation so precompilation stays silent; still `===`, the first access in a session prints the C-level `WARNING: Use of ERGMRank.fit_rank_ergm is deprecated…` under `--depwarn=yes` which `Pkg.test` sets (Julia warns once per deprecated binding, not on every access) — tests reach it only through `deprecated_access(expr)`, which redirects stderr to a file and asserts the text; removed in 0.3) with `method=:mple` (default) or `method=:mcmle`. The main method is `(rnet::RankNetwork, terms::Vector{<:AbstractERGMTerm}; kw...)`; a single term and a tuple forward to it, a `Network`/`AbstractMatrix` first argument throws `_not_a_rank_network` ("call as_rank_network(...) first"), and `_check_rank_terms(context, terms)` refuses any term without BOTH `compute(t, ::RankNetwork)` and `swap_change` methods (ERGM.jl's binary terms) up front, from the fitter and `simulate_rank_ergm` alike — never a `MethodError` from the design builder. **The two are different estimators, and `RankERGMResult.method` says which one a result is** (`objective` answers `:pseudolikelihood`/`:likelihood`; `is_exact` is `false` for both, for two different reasons stated in its docstring). `maxiter` caps the Newton iterations (100) or the MCMLE iterations (20); `se` resolves per method (`:hessian`/`:bootstrap` vs `:fisher`) and is validated by `Networks.check_se` against that method's tuple, so a wrong `se` names the right vocabulary.

   **`method=:mple`**: swap-based maximum pseudo-likelihood — for each ego and unordered alter pair, the observed relative order is logistic in θ'[g(y) − g(y_swapped)]. **Everything shared comes from Networks.jl by name and is never re-implemented here:** the optimizer `Networks.newton_fit` and kernel `Networks.logistic_derivatives` (`public`; `ERGM.newton_fit === Networks.newton_fit`, pinned), the floored z→p helper `Networks.z_pvalues` (there is no `_z_pvalues` in this package — `@test !isdefined(ERGMRank, :_z_pvalues)`), the `se=` validator `Networks.check_se`, the coefficient table `Networks.CoefficientTable` (`coeftable(fit)` IS what `show` prints), and the bootstrap loop `Networks.bootstrap_cov`. **Claim discipline:** this is NOT the MCMC MLE and must not be described as a "consistent" approximation to it — the swap comparisons multiplied into the pseudo-likelihood are not independent, and no asymptotic regime under which swap-MPLE is consistent has been established here. Nor does the pseudo-likelihood EVER coincide with the likelihood — not even for a term that decomposes over egos (there is no rank analogue of dyad independence: an ego's comparisons must form a total order): on the 4-actor network with `RankNodeICov([1,2,3,4])` exact enumeration of the 1296 orderings gives the MLE −0.0767 while the swap-MPLE is −0.0880 (an MCMLE run to `conv_threshold=0.01` at 16384 draws lands at −0.0772; at the default threshold it satisfies the convergence test at its swap-MPLE start and takes no step), pinned by the nested testset in the n = 4 enumeration testset. Each factor is the two-state conditional `P(y | {y, y_swapped})`, not "the order of j and k given the rest of the rankings" (a non-adjacent swap reorders j and k relative to the intermediate alters); say it that way. The DEFAULT SEs (`se=:hessian`) are the inverse observed pseudo-Hessian and are therefore expected to be anticonservative under dependence; say so wherever the estimator is documented.

   **The swap-MPLE can fail to exist, and every failure is loud** (warning at fit time + `approximations(fit)` entry + a line under `Converged:` in `show`; the three are derived from the same fields so they cannot disagree):
   - *Boundary statistic* (R's `drop=TRUE`): the design's response is identically `true`, so a column whose nonzero swap differences share one sign is at the boundary of its attainable range (`:min` → the observed ranking minimises it over every single swap, e.g. `RankInconsistency(rnet)` on `rnet`; `:max` → maximises it). Detected with `ERGM._boundary_columns_iterated(D, ones(m), ones(m))`, warned with `ERGM._warn_boundary` (R's "at their smallest attainable values" sentence — note it says "dyads", ERGM's noun), coefficient fixed at `∓Inf`, SE 0 (z = ∓Inf, p = 0 in the table), the rest fitted on the rows the dropped columns do not touch (`_rank_mple_fit_dropped`), `dof = count(isfinite, coef)`, `n_kept` recorded on the result and used by `bic`. If every row is touched, the remaining coefficients are **NaN, `converged = false`, "not identified"** — never a Newton "solution" on an empty design. `se=:bootstrap` is refused with an `ArgumentError` when a coefficient is fixed.
   - *Separation the column test cannot see* (a combination of statistics no single swap lowers): `ERGM._separated(f, D, ones, ones, θ, se)` — the 4-actor R test network under `RankDeference() + RankNonconformity()` IS such a design (direction (1, 1) gives Dβ ≥ 0 on every row; the baseline reported θ ≈ (9.4, 10.1), SE 7,066, `converged = true`). Now `converged = false` with R's "The MPLE does not exist!" wording (`_warn_separated_rank`). **Tests that only need "a well-posed two-term model" use `well_posed_network()` (6 actors), not `r_test_network()`.**
   - *Newton exhausting `maxiter`*: `converged = false`, warning quotes the gradient norm (`grad_norm` in the `_rank_mple_fit` return).
   - *Rounding-level stalls*: on a 2,040-row design (Hessian entries in the thousands) Newton stalls at the maximum with ‖∇ℓ‖ ≈ 5e-4, below the objective's rounding floor but above `sqrt(tol)`; `Networks.newton_fit` now declares convergence on the scale-free Newton decrement ½∇ℓ'(−H)⁻¹∇ℓ < tol (the reconciliation round adopted ERGMRank's request), so the local `_stalled_at_optimum` shim and its testset are deleted and the testset "newton_fit converges on the swap design without a local shim" pins the kernel's verdict on the Newcomb design directly.

   **Robust SEs** (`se_type` on `RankERGMResult`, reported by `Networks.se_method`): `se=:bootstrap` is a **parametric bootstrap** — simulate `n_boot` rank networks at θ̂ with the AlterSwap sampler (`simulate_rank_ergm`), refit the swap MPLE on each (`_rank_mple_fit` with `warn=false` is the shared core), empirical covariance — with the same API as `ERGM.mple`'s (`n_boot`/`boot_burnin`/`boot_interval`/`rng`), running on the ONE shared `Networks.bootstrap_cov` loop; never paste the loop in. A replicate without a finite refit (∓Inf/NaN/separated) is a NaN row of `fit.boot_replicates`, **excluded** from the covariance (ERGM.mple's round-3 pattern), warned about once and recorded in `approximations`; fewer than 2 finite refits throws. The point estimates are identical under both; only the covariance changes. On the test fixture the bootstrap SEs are more than **2× larger** than the Hessian ones — this package is where the anticonservatism bites hardest, because *every* rank fit has overlapping comparisons and there is no exact special case to exempt. `show`/`approximations` read `se_type` and drop the anticonservatism claim when a bootstrap was used, but keep the point-estimate caveat (swap pseudo-likelihood, no consistency claimed) in both — `is_exact` stays unconditionally `false`.

   **StatsAPI surface**: all ten verbs (`coef`, `stderror`, `vcov`, `confint`, `loglikelihood`, `nobs`, `dof`, `aic`, `bic`, `coeftable`), pinned by `Networks.check_statsapi(fit; strict=true)` for both methods. **`nobs` is per method**: the `n(n−1)(n−2)/2` swap comparisons under `:mple` (its observations) and R's `nobs.ergm` = `network.dyadcount` = `n(n−1)` under `:mcmle` (`_n_dyads`; `n_kept` of a `:mcmle` result is that too, so `bic` is on R's scale — `log(272)` on Newcomb, not `log(2040)`). Under `:mple`, `aic`/`bic` are the **pseudo**-AIC/BIC of the swap pseudo-likelihood (`bic` uses `n_kept`), not comparable to R's bridge-sampled `logLik`, and **NaN when `n_kept == 0`** (every comparison changes a dropped boundary statistic — `show` prints "not defined", never the `0.0` of an empty product); under `:mcmle` they are the AIC/BIC of the bridge log-likelihood (`NaN` with `bridge_rungs=0`). **The log-likelihood convention**: `loglikelihood` of a `:mcmle` fit is ABSOLUTE (θ̂'g − log Z(θ̂), `log Z(0) = n·log((n−1)!)` exact); R's `logLik` is RELATIVE to θ = 0 (ergm defines a valued model's null likelihood as 0), so `R = loglikelihood(fit) + n·log((n−1)!)` and AIC/BIC shift by `−2n·log((n−1)!)` (≈ 1042 on Newcomb). Stated in the `aic`/`bic` docstring, the estimation guide, the README and the migration table, and asserted against R's `logLik` by the fixture — never claim the numbers "are R's". Keyword vocabulary: `maxiter`, `n_sim`, `rng` (pinned via `Base.kwarg_decl`; never `max_iter`/`n_sims`/`seed`), and the MCMLE keywords are `ERGM.mcmle`'s, spelled the same (pinned against `Base.kwarg_decl(ERGM.mcmle)`).

   **`method=:mcmle` (finding N4, closed)** — the MCMC MLE, the estimator of R `ergm.rank`, in `_rank_mcmle`. **It is `ERGM.mcmle`'s iteration with the AlterSwap chain as the sampler, and nothing statistical is re-derived here**: the swap-MPLE start (`_rank_mple_fit` with `warn=false`; a boundary start is refused with R's sentence unless `init=` is given — then warned about, because a swap-local minimum is not proof that no MLE exists — and a separated start is refused pointing at `init=`, exactly as `ERGM.mcmle` refuses); the Hummel step length, the 95 % Mahalanobis radius (`quantile(Chisq(p), 0.95)`), the singular-covariance stop and the `max_step_norm` cap copied line for line from `mcmle.jl`; the convergence tests are `ERGM.mcmc_convergence` (public, imported by name; per-statistic t-ratios < `conv_threshold`, Hotelling T² with the Geyer ESS > `hotelling_alpha`, only at γ = 1); the report is an `ERGM.MCMLEConvergence` (public); the covariance is `ERGM._mcmle_covariance(final_samples, chain_lengths, nothing, nothing, p)` — V = Σ̂⁻¹ plus the Monte-Carlo component V·Σ_mc·V, so `stderror` includes the MCMC error and `show` prints R's "MCMC %" (`_mcmc_percent`, `fit.vcov_fisher` is V alone); the degenerate-sample warning is `ERGM._warn_degenerate_stats`. The two ERGM privates are listed in the reach-in testset (`@test_broken ispublic`) and requested `public`. **The sampler** is `_rank_stats_chain`: the ONE kernel `mh_toggle!` with the ONE proposal `_propose_swap` (shared with `simulate_rank_ergm`, same draw order), `change!` = `_swap_delta!`, `apply!` = `swap_ranks!` **plus `stats .+= delta`** — the running statistics are kept current from the accepted swap's change statistics, and `on_sample` copies them into a row: no `compute` per draw. `_rank_mcmc_sample` is `ERGM._mcmc_sample`'s contract: one chain on the caller's `rng`; `n_chains > 1` splits the draws (first `n_samples % n_chains` chains get one extra), draws one `UInt64` seed per chain from `rng` in order, runs each on `Threads.@spawn` with its own `Xoshiro(seed)` and concatenates in chain order — so a fit depends on `rng` and `n_chains` only, never on the thread count (`n_chains` must never default to `Threads.nthreads()`); the reproducibility testset pins bit-identity for the same `rng`, chain by chain against the seeds. **The log-likelihood** is `_rank_bridge_loglik`: θ̂'g_obs − [log Z(θ̂) − log Z(0)] − log Z(0) with `log Z(0) = n·log((n−1)!)` exact (`_log_n_orderings`) and the ratio by path sampling along θ_u = u·θ̂ (`_rank_bridge_logZ_ratio`: trapezoid over `bridge_rungs` segments, one seeded chain per grid point on its own task — `ERGM._bridge_logZ` with the uniform ordering model as the exact reference; θ̂ = 0 returns 0 without drawing). It runs after the final sample, so coefficients and SEs are bit-identical with `bridge_rungs=0` (then `loglik`/`aic`/`bic` are `NaN`, `show` says "not estimated", `approximations` records it — ERGM's policy). The n = 4 testset enumerates all (3!)⁴ = 1296 orderings and checks the bridge against the exact log-likelihood at θ̂ (< 0.05 at 32 rungs), the MCMLE against the exact MLE (< 0.25 SE) and `vcov_fisher` against the exact Fisher information. **Non-convergence is loud** in the ERGM pattern: `converged || @warn` after the loop quoting max t-ratio / Hotelling p / γ, `_nonconvergence_caveat` for `:mcmle` quotes the same numbers from `fit.mcmc_convergence`, printed under `Converged: false` and listed in `approximations`. A start that already passes both tests is returned unchanged (iteration 1, no Newton step), exactly as `ERGM.mcmle` returns its MPLE start — tests must not assume a step was taken.
5. **Simulation** -- `simulate_rank_ergm`: Metropolis with the symmetric AlterSwap proposal on the ONE shared kernel `ERGM.mh_toggle!` (item 28) — the move is `(ego, j, k)`, `change!` fills the kernel's `delta` with `_swap_delta!` (the per-term `swap_change`, O(n)–O(n²) per step) and returns `false` (a swap has no removal direction), `apply!` is `swap_ranks!`, `on_sample` pushes `copy(current)`. The sampled sequence is **bit-identical** to the pre-kernel, brute-force loop (same rng consumption order; one testset re-runs that loop verbatim with `_swap_delta_bruteforce` and compares, another pins five draws as literals recorded before the change) and a step allocates 0 bytes (doubling the burn-in adds exactly 0 bytes, pinned). **Burn-in/interval defaults are swap-scaled** (item 24e): `burnin=nothing`/`interval=nothing` on `simulate_rank_ergm`, `gof` and `fit_ergm_rank`'s `boot_burnin`/`boot_interval` resolve through `_resolve_mcmc_controls(rnet, burnin, interval)` → `_mcmc_defaults(rnet) = ERGM._mcmc_defaults(_n_comparisons(rnet))` (`public` in ERGM): `20 n_swaps` and `max(100, n_swaps ÷ 10)` with `n_swaps = n(n−1)(n−2)/2`, the rank analogue of the dyad count; an explicit integer is honoured. `n_sim < 1`, fewer than 3 actors and a θ/terms length mismatch are refused. **So is a non-finite coefficient** — `_check_finite_coefficients(context, terms, θ, fitted)` runs in `simulate_rank_ergm(rnet, terms, θ)`, `simulate_rank_ergm(fit)` and `gof(fit)`: a coefficient fixed at ±Inf by a boundary statistic or NaN (not identified) makes θ'Δ non-finite at every proposal, so the kernel would reject every swap and return copies of the starting ranking, which `gof` would print as a perfect fit (every simulated statistic equal to the observed one, MC p-value 1). The `ArgumentError` names the fixed and the NaN terms, points at `fit.converged`/`approximations(fit)` and at removing the term (R's `drop=TRUE`) — the same refusal as `se=:bootstrap`. Never let the sampler run at a non-finite θ.

## The swap MPLE is a logistic regression, and its loop is Networks.jl's (review finding 15)

The swap pseudo-likelihood **is** a logistic likelihood on the swap-difference rows `d = g(y) − g(y_swapped)` with the response identically `true` — the observed order is always the "success". So `_rank_mple_fit` carries no loop of its own (it used to: `hess .-= (pr*(1-pr)) .* (d * d')`, a fresh `p×p` outer product on every one of the `n(n−1)(n−2)/2` comparisons of every Newton evaluation, **229 KB and 0.20 ms per evaluation** on a 17-actor ranking). It builds the design with `_rank_design(terms, work)` — one dense `(comparisons × p)` matrix filled in place by `_rank_design!(D, Tuple(terms), work)` behind a function barrier, every row one statically dispatched `_swap_delta!` (the per-term `swap_change`: the 2,040-row Newcomb design takes 15 ms, was 1.0 s with brute-force differences; allocations ≤ `8·m·p + 4096` bytes, pinned) — and hands it to the shared **`Networks.logistic_derivatives(D, trues(size(D, 1)))`**, the same builder ERGM's MPLE, ERGMMulti's MPLE and TERGM's CMPLE run on: **192 bytes and 0.046 ms per evaluation**, 4.3x faster, allocations independent of the comparison count. **Never paste the loop back in**; if it needs a feature, add it to `Networks.logistic_derivatives`. An `@allocated` regression test pins the bound, and a companion test asserts `logistic_derivatives(D, trues(...))(θ̂)` reproduces `fit.loglik` — i.e. that the all-true logistic really *is* the estimator, not merely similar to it.

**Two estimators, two kinds of assertion (finding N4, closed 2026-09-12).**

- **`method=:mcmle` IS ergm.rank's estimator and is ASSERTED against it.** The testset runs it at ergm.rank's own budget, parsed from the fixture's `provenance.mcmc_control` (`n_samples=2048, burnin=8192, interval=512`, one chain), on two Julia seeds — seed 1 with `bridge_rungs=16, bridge_samples=512`, asserting `loglikelihood(mle) + 17·log(16!)` against `mle_loglik` within `loglik_sd_multiple × (mle_loglik_mc_se + julia_bridge_sd)` plus `nobs == mle_nobs`, `dof == mle_df` and the AIC/BIC shift; seed 2 with `bridge_rungs=0` (the bridge cannot touch θ̂ or the SEs) — and asserts `|coef − mle_coefficients| ≤ coefficient_sd_multiple × (mle_seed_sd + julia_seed_sd)` and `|stderror − mle_std_errors| ≤ std_errors_rtol × mle_std_errors`, every number read from the TOML. The `[tolerance]` block carries the provenance of each: `mle_seed_sd` (7.4e-4 / 5.6e-5) is ergm.rank over five further seeds; `julia_seed_sd` (5.1e-4 / 7.2e-5) is ERGMRank over `Xoshiro(1..5)` at the same budget, the five estimates listed; the multiple is 4 (beyond a 4σ band of the difference of two independent Monte-Carlo estimates — the largest deviation seen over the five Julia seeds was a quarter of the band: 1.26e-3 / 1.50e-4 against 5.0e-3 / 5.1e-4); `std_errors_rtol` is 0.15 (observed 0.06–3.7 %, both SEs include the MCMC-error component; still a quarter of the swap-MPLE's anticonservatism, which must keep failing it). The Julia mean sits 0.81 / 0.65 R seed-sd from R's estimate. **Do not raise any of these numbers**: a failure at 4 means the estimators (or the bridges) disagree, not that a seed was unlucky. Re-measuring `julia_seed_sd` or `julia_bridge_sd` after a change to the sampler, the iteration or the bridge is legitimate — do it with `scratchpad`-style runs over five seeds, put the new literals AND the five estimates in `test/fixtures/r/newcomb_rank.R`, regenerate the TOML with `Rscript` (the R values come back identical: the seeds are fixed), and say so in the CHANGELOG. The fixture testset takes ~2 min (two MCMLE fits at R's budget, ~25 s each, plus the 16-rung bridge at 512 draws, ~30 s) — that is the price of asserting against a real MCMLE and it is not to be cut by lowering the budget below R's.
- **`method=:mple` is a DIFFERENT estimator and its gap is CHARACTERISED, never tolerated.** `ergm.rank` fits the MCMC MLE; the swap pseudo-likelihood is not a noisy MLE. The testset asserts the **character** of the disagreement so a change in either direction is noticed:
  - **The observed sufficient statistics match exactly** (844, 12748) — deterministic, asserted at 1e-9. The term formulas are right.
  - **The gap is systematic, not Monte-Carlo.** swap-MPLE `[-0.14091, -0.0058538]` vs ergm.rank `[-0.15310, -0.0065927]`: **16x and 13x** `mle_seed_sd` (asserted > 5). No MCMC budget closes it — the MCMLE, at the same budget, sits inside 1 R sd.
  - **But it is small where it counts:** 0.30 and 0.43 of an ergm.rank standard error (asserted < 0.6). Same sign, same order, same substantive story. A different estimator, not a broken one — which is exactly what this package claims.
  - **The pseudo-Hessian SEs are anticonservative, and by a measured factor:** 3.9x (deference) and 2.0x (nonconformity) narrower than the MLE's. `se=:bootstrap` moves most of the way back (0.0280 vs R's 0.0404), and the testset asserts it does.

The README, the estimation guide and the `fit_ergm_rank` docstring all say the same thing: the swap-MPLE does not reproduce `ergm.rank`'s coefficients; `method=:mcmle` does.

## Exports: `using ERGMRank` must suffice

The module exports its own API AND the shared verbs a user needs with it: the statistic protocol `compute`/`name` (the ONE `Networks.compute`/`Networks.name`, reached through ERGM.jl — `ERGMRank.compute === Networks.compute` is pinned), the StatsAPI surface, and the result-metadata protocol (`fit_metadata`, `approximations`, `estimand`, `objective`, `is_exact`, `se_method`, `missing_method`). They are the same bindings every fitting package in the ecosystem exports, so co-loading (`using ERGM, ERGMRank, …`) leaves every verb defined and single-owned — pinned in a fresh process by the "using ERGMRank suffices" testset (`ERGM, ERGMRank` always; the rest of the family when the sibling checkouts and the root development environment are present and each sibling loads on its own). Never define a local `compute`, `name`, `gof` or `coeftable`; never `using ERGM: compute` in the docs — it is exported. ERGMRank does NOT re-export Networks: examples that build a `Network` say `using Networks`.

## Conventions

- All term structs subtype `AbstractERGMTerm` and implement `name()` (returning a dotted string like `"rank.mutual.3"`), `compute()` (returning `Float64`) and `swap_change()` (the exact change of a swap, allocation-free; the brute-force oracle is test-only).
- `RankNetwork` stores a dense `Matrix{Int}`; it does not wrap a `Network`.
- Rankings use values `1:(n-1)` per ego where GREATER value = HIGHER standing (matches R ergm.rank; note this is the opposite of "rank 1 = best").
- Functions mutating a `RankNetwork` use the `!` suffix convention (`set_rank!`).
- The module exports all public API symbols explicitly at the top of the module definition.
- Every exported name has a docstring with a runnable `# Example` block (pinned by the docstring-examples testset: every ```julia block of every exported docstring runs after nothing but `using ERGMRank`, **with stderr captured and required empty**, and **every top-level line ending in `# true` / `# false` (optionally `# true: …`) is ASSERTED against its claim** — a comment is a claim, so never write `fit.converged   # true` on a fit that does not converge; use `≈` for a floating-point claim); every README/docs `julia` block executes under `tools/check_snippets.jl`; the docs build is strict (`warnonly=false`, `checkdocs=:exports`), so an exported name with an ERGMRank docstring needs a `@docs` entry under `docs/src/api/`.
- Errors are actionable and name their context: the routine (`as_rank_network:`, `fit_ergm_rank:`, `RankNonconformity:`), the ego at fault, the attribute, the allowed vocabulary. The README's "Common mistakes" section quotes the exact texts; change a message and update it.
- `CHANGELOG.md` `[0.2.0] - Unreleased` has one entry per behavioural change (Breaking/Added/Performance/Changed/Known limitations/Fixed); a user-visible limitation is stated with the exact behaviour the user gets.
